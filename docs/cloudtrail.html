構成

managementで作る組織の証跡の設定により、全アカウント・全リージョンの操作がlog-archiveのバケットに直接保存されます。調査はauditからAthenaのSQLで行います。

設定内容

組織の証跡

  • 記録する操作：管理イベント（リソースの作成・変更・削除、サインインなど）。S3のオブジェクトの読み書きなどのデータイベントは、量と料金が大きいため記録しない
  • 全リージョンを記録する。SCPで拒否された、許可リージョン以外での操作の試みも記録される
  • ログファイルの検証を有効にする。ログが改ざんされていないことを、ダイジェストファイルで確かめられる
  • 保管期間は、AWS Configの記録と同じ365日（log_retention_days）

Athena

もの名前内容
ワークグループcloudtrail調査用のワークグループ。クエリの結果はathena-results-<auditのアカウントID>バケットに保存され、30日で削除される
テーブルcloudtrail.logslog-archiveのバケットの操作ログを読むテーブル

テーブルには、ログの保存場所に合わせて次の3つのパーティションがあります。検索するときは必ずdt（日付）で範囲を絞ります。絞らないと全期間のログを読むため、時間と料金がかかります。

パーティション値の例
dt2026/10/12（日付。yyyy/MM/dd）
accountアカウントID
regionap-northeast-1

運用手順

操作ログの調査

  1. auditアカウントに、SecurityAudit許可セット（security-auditorsグループ）またはAdmin許可セットでサインインする
  2. Athenaのコンソールを開き、ワークグループcloudtrailを選ぶ
  3. クエリエディタでSQLを実行する

SQLの例

特定のユーザーが行った変更（読み取り以外）：

SELECT eventtime, recipientaccountid, eventsource, eventname, awsregion, sourceipaddress
FROM cloudtrail.logs
WHERE dt BETWEEN '2026/10/01' AND '2026/10/12'
  AND useridentity.arn LIKE '%yamada%'
  AND readonly = 'false'
ORDER BY eventtime DESC
LIMIT 100;

特定のリソースを削除したのは誰か：

SELECT eventtime, useridentity.arn, eventname, requestparameters
FROM cloudtrail.logs
WHERE dt >= '2026/10/01'
  AND eventname LIKE 'Delete%'
  AND requestparameters LIKE '%my-bucket%'
ORDER BY eventtime DESC;

コンソールへのサインインの失敗：

SELECT eventtime, useridentity.arn, sourceipaddress, errormessage
FROM cloudtrail.logs
WHERE dt >= '2026/10/01'
  AND eventname = 'ConsoleLogin'
  AND errormessage IS NOT NULL
ORDER BY eventtime DESC;

注意点

  • Athenaは読み込んだデータの量に応じて課金される。必ずdtで日付を絞る
  • ログがS3に届くまで、操作から5〜15分ほどかかる。直近の操作は、各アカウントのCloudTrailコンソールの「イベント履歴」（直近90日、そのアカウント・リージョンの分だけ）の方が早く確認できる
  • 調査できるのは、auditにSecurityAuditまたはAdmin許可セットで入れる人だけ。SecurityAudit許可セットで読めるのは、操作ログと調査用のテーブル・クエリ結果だけ
  • 保存先のバケットとログは、SCPにより誰も削除できない
